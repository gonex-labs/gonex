# 接口约定：权限校验与请求转发（网关）

**关联规格**：[spec.md](../spec.md)（用户故事 3）

## ANY /{转发规则匹配的任意路径}

除本功能自身管理接口（`/api/gonex/**`）外，其余所有请求均进入网关转发链路。

**处理流程**：

1. **认证**：解析 `Authorization: Bearer <token>`；若缺失或对应会话已过期/已
   吊销，返回 `401`，MUST NOT 转发（FR-009、验收场景 3）。
2. **匹配转发规则**：按请求路径与方法查找 `Forwarding Rule`（data-model.md）；
   若无匹配规则，返回 `404`。
3. **权限校验**：若匹配到的规则要求 `required_permission_id`，校验当前用户
   所有角色权限并集（FR-013）是否包含该权限；不满足则返回 `403`，MUST NOT
   转发（FR-008、FR-009、验收场景 2）。
4. **转发**：校验通过后，将请求转发到 `upstream_url` 对应的下游业务服务，并
   将下游响应原样返回给客户端（验收场景 1）。
5. **下游异常处理**：下游服务不可用或超时时，MUST 返回明确的网关错误状态
   （如 `502`/`504`），不得使客户端请求无限等待（spec.md 边界情况）。

**响应状态码约定**：

| 状态码 | 场景 |
|---|---|
| 401 | 未认证或凭证已过期/已吊销 |
| 403 | 已认证但无权限访问该路径 |
| 404 | 无匹配的转发规则 |
| 502 / 504 | 下游业务服务不可用或超时 |

**审计**：仅对"无权限被拒绝"（可选，视审计粒度需求）与被转发请求本身不要求
逐条审计；FR-010 明确要求审计的是登录/登出与用户、角色、权限的管理操作，而非
每一次业务转发请求。
